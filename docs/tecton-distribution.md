# Tecton distribution for the test shell

The test environment consumes `@tecton/react` as an immutable local source package in `vendor/tecton-react`, pinned to upstream commit `424889e4ff47af48e6a8b138ad77421a5ce5014d`. Rspack compiles this installed package's TSX with the same React runtime as the shell and remote Apps. The package includes generated declarations in its `types` export condition, so a consumer's stricter TypeScript flags do not recheck the upstream implementation. No developer needs a second repository checkout or a declaration generation step to install or start the environment.

The package includes the actual `shell-01` header block and its command palette and shortcuts dialog, plus `AppFinder`, `AppShell`, `PageHeader`, common component dependencies, and the generated icon set. Public component subpaths retain their upstream names. Block imports retain upstream file extensions, for example `@tecton/react/blocks/shell-01/components/shell-command-palette.tsx`.

The artifact's manifest pins only dependencies reached by the selected runtime source. It omits the shadcn CLI, documentation tooling, chart libraries, and unrelated components. The small shadcn Tailwind stylesheet is included separately with its license and checksum. React and React DOM are peers so the consuming federation build controls their identity.

Import `@tecton/react/globals.css` once from the shell stylesheet. Its generated entry imports the original tokens, palette, base rules, fonts, and shadcn variants without changing any upstream source. Its `@source` path is relative to the installed package; it does not depend on the original repository's `apps/` directory. The shell stylesheet must add an explicit `@source` path for its own application code because automatic source detection is disabled.

Remote Tailwind input can use `@reference "@tecton/react/globals.css"` to make the theme and variants available without duplicating resets or fonts, then import `tailwindcss/utilities.css` and provide explicit source paths for the remote and its consumed Tecton package. The framework scopes the emitted remote CSS before federation loads it. CSS generation and browser validation must operate on the installed artifact, not the reference checkout.

After dependency installation, `node scripts/prepare-tecton.mjs --check` verifies the immutable source checksums and reproduces the generated CSS and all declarations without writing. Declaration generation uses the pinned TypeScript compiler and upstream strict compiler settings; it also checks the installed source against the original checksums. `node scripts/prepare-tecton.mjs` regenerates those distribution outputs. To restore the immutable snapshot, provide `--upstream <checkout>` at the exact pinned revision; changed upstream source fails checksum verification. A dependency upgrade requires an intentional revision, source-closure, checksum, and manifest review.

This remains a private source distribution, not a published component release. The inspected upstream revision supplies no package license declaration or repository LICENSE file; the included shadcn CSS retains its own MIT notice. PortalProvider is available from its normal subpath, but shipping it does not establish the separate overlay isolation acceptance gate.
